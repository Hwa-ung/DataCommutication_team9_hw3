# DataCommutication_team9_hw3

TCP 소켓과 스레드를 사용하는 장애 허용 워커 링 과제입니다. 코디네이터가
1,000개 작업을 워커 10개에 배정하고, 워커는 링의 다음 워커에 중간 계산값을
체크포인트로 전송합니다. 최종 목표는 1부터 100,000,000까지의 소수 개수
**5,761,455**를 계산하면서 각 작업의 결과를 정확히 한 번만 확정하는 것입니다.

## 구성

| 파일 | 역할 |
| --- | --- |
| `coordinator.py` | 작업 배정, heartbeat 장애 판정, 작업 인계, epoch/소유자 확인 및 결과 확정 |
| `worker.py` | 소수 계산, 체크포인트 송수신, 모의 장애 및 재참여 |
| `launcher.py` | 워커 10개 실행, READY 대기, 무작위 CRASH/RESTART 명령 전송 |
| `tests/test_regressions.py` | 장애 복구, 동시성, 메시지 검증 및 종료 처리 회귀 테스트 |
| `tests/run_integration.py` | 실제 10개 워커와 1,000개 작업을 사용하는 통합 테스트 |

Python 3.9 이상을 사용합니다. 별도 패키지 설치 없이 표준 라이브러리만 필요합니다.
워커 포트는 TCP **7001~7010**으로 고정되어 있으므로 같은 PC에서 여러 실행을
동시에 시작하지 마세요.

## 실행

저장소 디렉터리에서 터미널 두 개를 사용합니다.

터미널 1 — 코디네이터:

```sh
python coordinator.py --host 127.0.0.1 --port 9000 --log-dir logs/run
```

터미널 2 — 워커 실행 및 장애 주입:

```sh
python launcher.py --coord-ip 127.0.0.1 --coord-port 9000 --seed 42 --step-delay 100 --log-dir logs/run
```

- `--step-delay`: 계산 단계별 지연 시간(ms), 기본값 100. 음수는 허용하지 않습니다.
- `--seed`: 장애 대상과 시점에 사용하는 난수 seed, 기본값 42.
- 코디네이터는 heartbeat가 3초 이상 없으면 SUSPECT, 5초 이상 없으면 DEAD로 판정합니다.
- 런처는 모든 워커가 READY가 된 뒤 장애를 주입하며, 80초 이후에는 새 장애를 만들지 않습니다.
- 정상 완료 시 코디네이터 로그에 `[VERIFY] PASS`, `all_done=True`,
  `all_commit_once=True`, `double=0`이 기록됩니다.
- 코디네이터 검증 실패 또는 런처/워커의 감지된 실행 오류는 종료 코드 1로 보고합니다.

원격 코디네이터에 연결할 때는 코디네이터의 `--host 0.0.0.0`과 실제 접근 가능한
`--coord-ip`를 사용하세요. 워커들은 런처와 같은 PC에서 실행됩니다.
`--peer-ip`는 다른 워커가 접근할 수 있는 주소이며, 같은 PC에서 실행할 때는
기본값 `127.0.0.1`을 사용할 수 있습니다.

## 버그 수정 및 변경 사항 (2026-10-24)

| 대상 | 기존 문제 | 수정 내용 |
| --- | --- | --- |
| 결과 확정의 동시성 | RESULT에서 DEAD 여부를 검사한 뒤 잠금을 풀어, 장애 판정과 결과 확정이 서로 끼어들 수 있었음 | 워커 상태 확인부터 작업 소유자·epoch 확인 및 DONE 전환까지 `wl → task.lock` 순서로 보호 |
| 메시지와 작업 번호 | 다른 워커 ID로 REQ/REJOIN/RING_OK/HB를 보내 상태를 바꿀 수 있었고, 음수 task ID가 Python 음수 인덱스로 처리됨 | 등록 소켓과 워커 ID의 일치 여부 확인, 작업 번호·epoch·결과값 범위 검사, 중복 HELLO 방지 |
| 인계 대상이 없는 장애 | 모든 워커가 DEAD일 때 남은 작업을 넘기지 못하면 이후에도 재인계하지 않아 완료가 멈출 수 있었음 | 매 장애 검사에서 DEAD 소유자의 미완료 작업을 재확인하고, 재참여한 워커에 남아 있던 작업은 epoch를 증가시켜 재전송 |
| 워커 장애 처리의 경쟁 상태 | CRASH 상태 전환과 큐·체크포인트 초기화가 분리되어 늦은 배정/체크포인트가 다시 들어갈 수 있었음 | 일관된 잠금 순서로 상태와 데이터 초기화를 보호하고, 배정·인계·체크포인트 수신 시 상태 재확인 |
| 잘못된 상태 전환 | 중복 RESTART가 실행 중인 워커를 REJOINING으로 바꾸거나, 늦은 WELCOME이 CRASHED 워커를 되살릴 수 있었음 | 허용된 이전 상태에서만 전환, 재참여 재시도 시 crash generation과 종료 여부 확인 |
| 연결 종료와 실행 종료 | 코디네이터 연결이 끊겨도 계산/heartbeat 스레드가 대기하고, 종료 중에도 계산·송신이 이어질 수 있었음 | 연결 종료/코디네이터 송신 실패 시 모든 대기 스레드에 종료 알림, 단계 지연도 즉시 중단 가능하도록 변경 |
| 잘못된 메시지와 체크포인트 | 빈 줄 또는 숫자가 아닌 CKPT 필드로 수신 스레드가 종료되고, 새 epoch의 체크포인트를 과거 인계에 사용할 수 있었음 | 메시지 형식·범위 확인, 잘못된 런타임 제어 메시지 무시, 인계 epoch보다 이전인 유효 체크포인트만 사용 |
| 런처 시작 및 자원 정리 | READY 이전 연결 종료 시 무한 대기하고 중복 READY도 새 워커처럼 계산함. 시작 실패 시 자식 프로세스가 남을 수 있었음 | 워커별 READY 집합과 60초 제한 적용, EOF를 오류로 처리, 성공/실패/중단 경로에서 소켓과 자식 프로세스 정리 |
| TCP 송신 실패 | 비차단 `sendall()` 실패를 로그만 남기고 넘어가 작업 메시지가 유실되거나 프레임이 잘릴 수 있었음 | 코디네이터/런처 송신에 제한 시간 적용. 코디네이터 송신 실패 시 연결을 종료하여 장애 감지·작업 회수로 이어지게 하고, 런처는 오류로 종료 |
| 시간 측정 및 로그 | 시스템 시각 변경이 장애 판정/장애 일정에 영향을 주고, 로그 파일을 닫는 중 다른 스레드가 기록할 수 있었음 | 경과 시간은 `time.monotonic()` 사용, 로그 기록·닫기를 같은 잠금으로 보호 |

추가로 워커 ID와 음수 지연 시간을 실행 전에 검사하고, 재연결 실패 시 소켓을
닫도록 변경했습니다. 테스트 결과 파일은 `.test-runs/`에 저장하고 Git 추적에서
제외합니다. 기존 `logs/`의 기록은 이전 실행 자료입니다.

## 테스트

회귀 테스트:

```sh
python -m unittest discover -s tests -v
```

실제 프로세스 통합 테스트는 다음 명령을 **차례대로** 실행합니다.
각 명령은 코디네이터와 런처를 자동으로 시작하고, 로그 저장 위치를 출력합니다.

```sh
python tests/run_integration.py --step-delay 0
python tests/run_integration.py --step-delay 100 --seed 42
python tests/run_integration.py --step-delay 100 --seed 7
python tests/run_integration.py --step-delay 100 --disconnect-coordinator
```

지연 0인 테스트는 빠른 전체 계산 검증입니다. 실행 환경에 따라 첫 장애 주입
이전에 완료될 수 있습니다. 지연 100인 테스트는 실제 CRASH, TAKEOVER, REJOIN을
포함하며 각 실행에 약 2분이 걸립니다. 연결 종료 테스트는 실행 중 코디네이터를
종료하여 워커와 런처가 대기 상태에 남지 않고 오류를 보고하는지 확인합니다.

통합 테스트는 합계 5,761,455, 정확히 1,000개의 COMMIT, 작업별 1회 확정,
중복 확정 0개, 워커 종료 및 예외 traceback 부재를 확인합니다.

### 검증 결과 (Windows, Python 3.13)

| 검증 | 결과 |
| --- | --- |
| 회귀 테스트 | 26개 모두 통과 |
| `--step-delay 0` | 1,000개 작업 완료, 합계 5,761,455, 중복 확정 0개 |
| `--step-delay 100 --seed 42` | 약 119.9초, DEAD 8회 / TAKEOVER 7건 / REJOIN 8회, 최종 검증 PASS |
| `--step-delay 100 --seed 7` | 약 118.8초, DEAD 8회 / TAKEOVER 8건 / REJOIN 8회, 최종 검증 PASS |
| 실행 중 코디네이터 연결 종료 | 워커 종료 및 런처 종료 코드 1 확인, 대기 상태에 남지 않음 |
| Python 구문 컴파일 / `git diff --check` | 통과 |

DEAD 횟수와 TAKEOVER 건수는 같을 필요가 없습니다. 장애 시점에 미완료 작업이
없는 워커라면 인계할 작업도 없습니다. 실행 시간과 장애별 작업 배정은 환경과
스레드 실행 순서에 따라 달라질 수 있습니다.

### 지원 범위

이 과제의 CRASH/RESTART는 워커 프로세스를 유지한 채 상태와 작업 큐를 바꾸는
**모의 장애**입니다. 실제로 종료된 워커 프로세스의 자동 재생성이나 코디네이터
상태의 디스크 복구는 구현하지 않습니다. 런처가 실제 자식 프로세스 오류를 감지하면
남은 워커를 정리하고 실패를 보고합니다. 소켓과 ID의 일치 검사는 연결된 워커를
구분하기 위한 검사이며, 별도의 인증 프로토콜은 아닙니다.
